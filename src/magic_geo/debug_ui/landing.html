Open-source planet generator

Procedural planets, simulated from plate to biome.

magic-geo grows a world the way a planet grows: plates move, mountains rise, a seasonal climate sets rain and ice, rivers carve valleys, soils and ecosystems follow, and settlements find their place. One YAML file in, a fully explorable world out.

Why magic-geo

Worlds that make sense — and tell you where they don’t.

Causal, not cosmetic

Every field is computed from what came before it. Plate motion builds relief. Relief shapes the seasonal climate. Climate drives runoff, erosion and ice. Soils, biomes, resources and settlements follow. A coastline in the wrong place is a bug, not noise.

Explore every layer

Grab the globe and fly anywhere, or unroll it into an equirectangular or Mollweide map without losing your place. Scrub through stages and months, turn on relief, cell outlines and places, and click any cell to see all of its fields. Around 500 layers are grouped by topic, searchable and documented in place.

Honest about uncertainty

Unavailable estimates are shown as unavailable, never as zero. Each field gets a colour scale that fits it — sea level on elevations, zero on signed values, labels for identifiers — and the browser and CLI draw the same colours. Budgets carry their residuals. Every output says what it is and what it is not.

Reproducible by design

Running the same seed with the same configuration produces the same planet. Configurations are validated against a versioned schema, and saving is atomic and checks the file’s revision. A world can be regenerated, compared and shared.

Scriptable end to end

The Python API, the CLI and the REST API all run the same pipeline. Generation, validation, rendering and export run as typed background jobs, which you can queue from the browser or from your own scripts.

Ready for art and games

Export SVG and raster maps, columnar Parquet/Arrow caches, ParaView stages and Rerun recordings. You can also export a PNG reference with a matching GPT Image prompt that includes an exact colour key.

How it works

Configure → generate → explore → export.

  1. 1

    Configure

    Start from a profile such as earthlike, smoke or default. Name your world, then pick a seed and a resolution. Experts can edit the full YAML with live schema reference and validation.

  2. 2

    Generate

    The generator builds the mesh, then runs tectonics, the seasonal energy balance, hydrology, erosion, cryosphere, soils, ecology and human geography. Each phase reports progress, and you’re notified when the map is ready.

  3. 3

    Explore

    Open the world on the globe. Pin the layers you care about and play through months or stages. Inspect cells and their neighbours, and browse every record family as a table.

  4. 4

    Export

    Validate the world against its physical checks, render maps, or feed the exported tables and images into your own tools.

A C++20 core does the heavy simulation and is loaded through a frozen C ABI. Python handles configuration, validation, enrichment and file output. Use --geo-only to stop at natural geography.

Quickstart

From clone to planet in minutes.

You need Python 3.11+, CMake 3.20+ and a C++20 compiler. OpenMP is used when found, and a CUDA toolkit enables the GPU backend.

git clone https://github.com/Andres77872/magic_geo.git
cd magic_geo
./scripts/dev.sh          # builds the core and serves http://127.0.0.1:8642

Open the address, choose New world, pick a profile and select Create & generate. The map opens when it’s ready.

python -m pip install -e .
cmake -S . -B build && cmake --build build
magic-geo generate --config configs/earthlike_seed.yaml \
  --output runs/earthlike/world.json --summary runs/earthlike/summary.md
magic-geo render --world runs/earthlike/world.json \
  --output runs/earthlike/world.svg --projection mollweide --labels

Add --cells 512 for a fast smoke run, or --geo-only to stop after natural geography.

from magic_geo import create_config
from magic_geo.api import generate_world

config = create_config("earthlike", {"run.seed": 20240117, "mesh.cell_count": 2048})
world = generate_world(config)
print(len(world["cells"]), "cells generated")

Profiles, overrides and the JSON Schema are all available from Python. See the Python API guide.

cp .env.example .env
mkdir -p worlds
docker compose up --build -d   # workbench on http://127.0.0.1:8642

Worlds persist in ./worlds. Run any CLI command with docker compose run --rm magic-geo ….
