# Simulation coherence and scientific validation

## Assessment

Magic-geo is a causal procedural planet generator with several conservative numerical operators and extensive equation replay. Its overall scientific realism remains partly demonstrated. A fresh baseline using the checked-in 21-scenario matrix passed 19 scenario policies and all 26 paired responses; the canonical Earth member covered all 22 external reference metrics but matched only 17. Passing equation replay, deterministic regeneration, or artifact-presence checks does not resolve those five observational mismatches.

The most immediate correctness problems were at interfaces between otherwise functioning components. Hydrology's lake classification could be overwritten by the soil stage. Lake cells could acquire terrestrial biomes and settlements. The geo-only Python path computed a permafrost regional aggregate before its seasonal input was available. Suppressing cell output also suppressed the inputs needed to construct later records. Browser request races could associate validation or saving with a different editor state from the one submitted.

The revision addresses these defects and corrects exported astronomical insolation. A subsequent [explicit C++ seasonal model](seasonal_climate_native_integration.md) now produces temperature from a periodic radiation/storage/transport budget and retains its independent replay evidence. Default C++ and existing C ABI/Python/CLI/web generation retain the prior parameterized temperature model and its honestly separated solar diagnostic. Neither path establishes physical-time geological evolution, a closed planetary water inventory or a fully coupled atmosphere–ocean climate.

This report combines current implementation evidence with primary scientific references. Reproduction commands and executable checks are included below. The previous [natural generation and maturation audit](geo_generation_maturation_deep_audit.md) contains the broader crust-transport and reservoir analysis; statements there that all current layer dependencies are correct are qualified by the interface defects documented here.

## What layer order must guarantee

A dependency is more than the presence of a named layer. A consumer needs the correct revision of its prerequisites, consistent units, and a clear distinction between a physical state and an explanatory diagnostic. A populated field containing a stale/default value can be more misleading than a missing field, because it passes simple presence tests.

The reviewed system has three relevant clocks. Native maturation advances a nominal geological coordinate. Climate and hydrology then diagnose conditions on the stabilized surface. Python adds linked descriptions and reconstructed histories after the native result has been serialized. Browser operations introduce a fourth, unrelated sequence: asynchronous requests and output publication. Ordering must be correct within each sequence and at each handoff.

| Producer | Required before consumer | Reason and invariant |
|---|---|---|
| Planet parameters and spherical mesh | Plate assignment, areas, distances, transport | Cell area and geometry set the scale of every extensive inventory. A display projection cannot define physical adjacency. |
| Plate/crust transport and tectonic tendencies | Committed terrain and subsequent sea level | A terrain mutation invalidates the water mask and any drainage derived from the old surface. |
| Sea-volume solve and marine connectivity | Marine-influenced climate, terrestrial water routing | `is_water` represents marine water in this schema; it cannot be assumed to include lakes. |
| Climate and hydrologic depression budget | Lake type, overflow, soils, aquatic biome | A downstream land classifier must preserve basin-level hydrologic decisions. |
| Stabilized terrain, hydrology, ice | Native soils, resources and settlement candidates | Submerged surfaces are not ordinary settlement candidates. |
| Monthly climate and soil diagnostics | Permafrost regions and their means | Freezing-month statistics must come from current monthly temperatures, not an absent or stale cached count. |
| Physical and water diagnostics | Ecosystem/resource descriptions | Linked records must reference the current water, soil and biome state. |
| Ports in a full world | Reef records with nearby-port links | Moving every nominally natural enricher before all human enrichers would break a real optional link. Geo-only deliberately omits it. |
| Complete internal cells | Final output filtering | An output preference must not remove simulation prerequisites before enrichment. |
| Submitted editor snapshot | Validation result and save retry | An answer about old YAML cannot label current edits as valid; conflict retry must use the submitted filename and bytes. |
| Manifest revision and mesh buffers | Map selection/export statistics | Mesh vertices and simulation cells have different cardinalities. |

The revised Python API shares the physical prerequisite sequence and ecosystem/resource sequence across the two generation entry points. It preserves the required port boundary in the full path. This is an explicit, centralized execution sequence, not a general dependency scheduler. Future enrichers still need an actual input/output review before insertion.

The native maturation sequence evaluates several tendencies from a prior stabilized state before committing terrain. That is a numerical coupling choice, not an ordering error by itself. Its scientific adequacy requires tests of the combined operator. Research on atmosphere–ocean–ice coupling shows that correct individual components can still exhibit large coupling errors or non-convergence, particularly at abrupt parameterization transitions. Consequently, single-process replay and a controlled fixed-domain convergence result cannot certify the complete moving-world calculation.[^1]

## Hydrology, lakes and terrestrial classification

The baseline native environment stage assigned lake categories, then allowed river/alluvial and volcanic branches to overwrite some of them. It also recomputed fresh versus saline status from local aridity after hydrology had already selected a basin state using water supply, evaporation and overflow. These operations could produce an internally inconsistent world even when each branch reproduced its own formula perfectly.

Direct baseline generation at 512 cells and one erosion step reproduced settlements on lake cells 234 and 56 for seed 1234, and on cells 283, 469 and 492 for seed 3003. Seed 1234 also produced alluvial wetland classifications on standing lake cells. These are specific reproduction cases, not statistical estimates of failure frequency.

The revision makes the hydrologic lake decision authoritative for subsequent classification. Standing fresh and saline water keep aquatic soil/biome precedence. A dry saline depression remains distinguishable from an occupied saline lake. Settlement scoring and selection exclude standing lakes, with the Python selection replay and model declaration updated accordingly. This changes settlement counts and downstream social history for some seeds, which is expected when invalid candidates are removed.

The scientific basis is the basin water and solute balance, not a universal rule that every closed basin is saline. USGS reports that terminal lakes can have widely varying salinity and that not all have high salinity. Water inflow and evaporative loss matter, as do sources and retention of dissolved material.[^2] The current code still uses a classification proxy; it does not evolve a dissolved-salt mass reservoir. Preserving hydrology's classification fixes competing ownership without claiming a chemical lake model.

The Python energy diagnostic had a related schema mistake. Its water-albedo branch tested only `is_water`, leaving native standing lakes to land-cover branches. It now recognizes `is_lake`, gives thick ice precedence, and applies no land-only aridity/snow brightening to open lake water. Dry salt flats remain land. The albedo values and greenhouse treatment are empirical; correcting category selection does not calibrate those coefficients.

Priority-Flood provides a sound basis for drainage preprocessing on regular or irregular meshes. Its guarantee that filled terrain drains is a computational property, not evidence that natural closed basins should be eliminated.[^3] The implementation therefore needs separate identities for physical topography, numerically corrected routing surfaces, standing water, and preserved natural depressions. The five remaining Earth-fit failures include excess endorheic area, so changing depression policy merely to force drainage would conceal rather than explain the discrepancy.

## Astronomical sunlight

The prior Python formula multiplied an affine cosine-of-latitude weight by a bounded seasonal factor and an inverse-square orbital factor. This could not produce a dark polar winter, retained an equatorial annual maximum at all obliquities, and treated equally spaced true anomaly as equally spaced time. The last error overweights the short interval near periapsis on eccentric orbits.

Daily insolation is the integral of positive solar zenith cosine over a rotation, scaled by stellar irradiance and inverse-square distance. Calendar definitions and the time measure matter when forming seasonal or annual means. Paillard's treatment explicitly distinguishes these averaging choices and identifies eccentricity, obliquity and climatic precession as separate inputs.[^4] The climlab reference implementation documents the corresponding daily geometry, declination and sunrise/sunset relations.[^5]

The new `insolation.py` uses these equations:

```text
M = E − e sin(E)                         Kepler equation
r/a = 1 − e cos(E)                       orbital distance
δ = asin(sin(ε) sin(λ))                  solar declination
A = sin(φ) sin(δ)
B = cos(φ) cos(δ)
H₀ = acos(−A/B)                         when a sunrise/sunset exists
Q = S₀ L (a/r)² [H₀ A + B sin(H₀)] / π  daily mean, W/m²
```

Here φ is latitude, ε obliquity, λ solar longitude, e eccentricity, E eccentric anomaly, and M mean anomaly. For continuous daylight, the daily mean is `S₀ L (a/r)² A`; for polar night it is zero. Comparing A and B avoids the singular `tan(latitude)` expression at the poles. There is no additional factor of one quarter in the local daily mean.

Each output month is an equal-duration interval whose boundaries are found by solving Kepler's equation. Integration within the interval uses true anomaly ν and the exact change of variable `(a/r)² dM = dν/sqrt(1−e²)`. This cancels the sharp periapsis irradiance peak against the short residence time. The maximum angular spacing is `2π/768`; highly eccentric months receive samples in proportion to their angular span, instead of an inadequate fixed time allocation.

The producer uses bisection and a half-angle orbital transformation. The independent validator uses safeguarded Newton iteration. The interval mean distance factor is the exact ratio `Δν/[ΔM sqrt(1−e²)]`; angular quadrature is needed only for daily solar geometry. Orbit geometry is cached per configuration because it is shared across cells. The accepted eccentricity domain `[0,1)` is preserved, including values arbitrarily close to one, with explicit metadata that orbital motion during a rotation is not resolved. Near-parabolic orbits are numerical stress cases, not claims of habitable or dynamically realistic planets.

The implementation retains an explicit convention where periapsis occurs at the center of month index zero and solar longitude there is −75 degrees. In a circular orbit this gives a northern summer solstice at index 5.5. This fixed phase is an implementation assumption; the configuration does not expose climatic precession. The semimajor axis is implicitly 1 AU, and `stellar_luminosity` scales the irradiance there. The model should not be described as a general orbital ephemeris or an instantaneous model of a synchronously rotating planet.

Several tests distinguish scientific correctness from self-consistent replay. At equatorial equinox, the mean is `S₀/π`. At a pole during summer solstice it is `S₀ sin(ε)`; the winter pole receives zero. Independent integration of a rotating surface normal against a fixed Sun direction checks the local result without using the sunrise equation. Equal-area latitude integration checks the global annual relation:

```text
<Q>sphere,year = S₀ L / [4 sqrt(1 − e²)]
```

The test grid checks zero, Earth-like, 60-degree and 90-degree obliquities, including eccentricity 0.8. Additional stress tests extend eccentricity to the largest binary64 value below one. Separate orbital tests verify that the annual average of `(a/r)²` is `1/sqrt(1−e²)`. These checks address the normalization and time-weighting defects that ordinary replay missed.

High-obliquity climate research finds that above roughly 54 degrees the annual polar solar input exceeds the equatorial input; it also shows that climate response depends on coupled ocean, atmospheric and sea-ice transport.[^6] The corrected solar geometry reproduces the reversal. For a circular orbit at 60 degrees, the calculated annual polar input is approximately 375.18 W/m² versus 334.00 W/m² at the equator. Those values are calculation outputs under the declared assumptions, not observational targets.

Existing `mean_*` energy summaries remain arithmetic cell means for compatibility. New `area_weighted_mean_*` fields integrate the five annual fluxes using each cell's physical area: incoming sunlight, absorbed shortwave, outgoing longwave, greenhouse trapping and net radiative balance. JSON output and Markdown summaries expose these fields. They require complete finite positive area coverage; incomplete or unrepresentable coverage produces `null` in JSON, with explicit availability, valid-cell-count and represented-area metadata. No area defaults to one. Independent unequal-area arithmetic, uniform-cell subdivision, stale-weight mutations and invalid-area cases check these summaries. Correct spatial integration does not establish planetary energy conservation: the flux fields remain final-state diagnostics of a separately forced temperature model.

The zero-greenhouse reference temperature now uses the same emissivity as the emitted longwave equation: `T = [absorbed/(0.96 σ)]^(1/4)`. Previously the equilibrium used σ while outgoing radiation used `0.96 σ`, leaving a nonzero flux residual even at the declared equilibrium. A zero-greenhouse, zero-current test now checks that temperature and flux residuals both vanish. The emissivity-scaled Stefan–Boltzmann relation is the standard graybody form.[^10] This is local consistency within the graybody diagnostic, not proof of a globally balanced atmosphere.

An accepted endpoint combination—luminosity 100 and eccentricity immediately below one—also exposed subtractive cancellation: a zero-greenhouse calculation reported 0.000732 W/m² of trapping while absorbed flux was about 2.1×10¹² W/m². The producer now evaluates the fourth-power temperature increment in factored form; independent replay uses its binomial expansion. Zero thermal increment gives exactly zero trapping, without subtracting nearly equal large fluxes. The existing 1 K radiation floor and clipping of negative trapping are preserved.

Net flux still subtracts large independently calculated terms. Its replay therefore includes a roundoff allowance of 16 binary64 ulps of the largest independently replayed parent flux. Stress inherits that allowance through its `/220` flux contribution; arithmetic and area means propagate the respective weighted allowances. Other fields retain the existing tolerance. Tests require exact and near-equilibrium replay, reject resolvable alterations at both ordinary and extreme flux scales, and verify that high-stress counts exactly classify the published six-decimal stress values. These are numerical-consistency corrections, not relaxed Earth-fit envelopes.

This improvement does not yet change the native temperature, precipitation or cryosphere forcing. The next climate implementation should consume the same astronomical forcing in the native climate step and explicitly represent the energy response, heat transport and storage. It must then be checked against Earth reference data and high-obliquity benchmarks. Simply substituting local instantaneous equilibrium temperature would ignore atmospheric/oceanic transport and could make the generated world less realistic.

## Python generation and validation

Full and geo-only generation previously duplicated a long list of enrichers. The geo-only sequence placed permafrost diagnostics before biome diagnostics supplied `frost_months`, so regional freezing-month means could silently read zero. Sharing the prerequisite sequence removes this divergence. Permafrost also now derives freezing counts from the authoritative monthly temperatures, so direct enrichment is robust to missing or stale cached biome counts.

The new regression independently counts subfreezing months from the monthly values and compares regional aggregates with member cells. A validator now checks regional means for permafrost extent, active-layer depth, ground-ice content, and frost months. This specifically catches stale summaries; it does not certify the empirical permafrost formula as a thermodynamic frozen-ground solver.

Full generation with `output.include_cells=false` previously passed that preference into native serialization before Python enrichment. The resulting partial data could retain native settlements/resources while later diagnostics were absent or empty. Generation now requests cells internally, completes enrichment, and clears the cell array only at the output boundary. A same-seed comparison requires equality of all non-cell products between the two output choices.

Cell-free exports remain unsuitable as standalone inputs to cell-level rendering or complete world validation. The documentation now states that restriction. Geo-only generation retains its requirement for cell data. This preserves the meaning of the existing option while preventing output formatting from altering simulation semantics.

The full regression run also exposed a CLI economy-validation defect after the corrected settlement inputs produced a declining-treasury history. The producer and independent causal replay include the opening treasury in the historical peak, while the CLI had checked closing balances only. In the reproduced zero-erosion world, the opening balance is 6.737690 index units and every closing balance is lower. The CLI now includes both ends of each interval. Tests require the valid history to pass and reject a peak that omits its opening balance. This corrects verification of the declared synthetic economy model; it does not calibrate that model against historical economies.

Several society mutation tests required a more populated control after invalid lake settlements were removed. The existing `mid_512` fixture supplies borders, campaigns, frontier towns and cross-language links that `small_smoke` no longer supplies. Only the affected tests changed fixtures. Dynasty genealogy literals were refreshed to the corrected causal inputs, and river-slope mutations now select a nonzero-slope channel. Their required failure branches remain asserted; an unrelated morphology failure was removed from a deliberately flat depression cycle, with an explicit assertion that morphology is unchanged there.

## Browser and API integration

The reviewed workflow is local configuration editing, validation, saving, background generation, cache publication, map loading and export. Its central correctness requirement is that every displayed result has an unambiguous input identity. Validation of old YAML is not validation of the currently visible text. A successful file save is not evidence that a subsequent generation request uses that file.

The configuration workflow now captures the submitted editor state. Late validation results cannot mark newer edits as valid. Save-conflict handling preserves the submitted filename and YAML rather than rereading mutable fields during the retry. Saving a custom configuration updates the generation configuration path. Numeric operation inputs accept decimal values supported by the API.

A live run through saving a custom configuration, generating 128 cells, and selecting the resulting cache exposed a separate mesh integration defect. Rendering geometry used 884 vertices for that world, but the UI treated the vertex-associated cell-ID buffer length as a world-cell count. Those counts have distinct meanings: triangles can repeat a cell ID at multiple vertices. The map must use the manifest/mesh cell count for per-cell values and coverage statistics, while retaining the vertex index for rendering.

Behavioral JavaScript tests exercise request races and operation defaults. Server/job tests check the corresponding transport and persisted results. A browser run supplements those tests by checking the complete saved-config-to-map path. Screenshot inspection or individual green endpoints alone cannot establish that input identity survives the whole workflow.

## Earth reference fit

The fresh pre-change matrix used the unmodified `configs/earthlike_seed.yaml` and the checked-in empirical bundle. It reproduced the previous audit's incomplete fit. The canonical world had an ocean area fraction of about 0.608, a global mean temperature of 15 degrees C, and mean land precipitation near 809 mm/year. These are generated statistics; the prescribed/centered temperature relation means the global average is not an independent prediction.

The [relief and continental-margin audit](relief_margin_calibration_audit.md) provides controlled ablations, held-out input interventions and source comparisons. It finds that excess ocean-basin capacity and positive relief already exist at initialization, excludes repeated target-offset application in the inspected runs, and identifies oceanic treatment of nominal continental margins as a material model gap. Increasing continental fraction alone improved one canonical metric but worsened ocean coverage and held-out results, so it was rejected as a standalone fix. A subsequent [offline column-buoyancy prototype](relief_buoyancy_prototype.md) reduced initial relief on both tested 4096-cell seeds while preserving crust columns, but failed to establish adequate submerged margins. One coarse-mesh variant failed its independent water-volume constraint and was explicitly rejected. Neither experiment changed production coefficients or presets.

These are declared model-fit envelopes, not confidence intervals. Increasing tolerances would not improve the simulated world. The relevant next analysis is to attribute the relief/water mismatch to crust initialization, equilibrium relief changes, dynamic tendencies, sediment redistribution and volume-constrained sea level. Coastline fraction also depends on spatial resolution and adjacency, so it needs source-matched sampling rather than an arbitrary universal target.

NOAA ETOPO 2022 provides surface and bedrock variants and combines terrestrial relief with bathymetry.[^7] Reference comparisons must preserve the selected variant and distinguish below-datum surface from the connected marine inventory. HydroBASINS has its own hierarchy and endorheic connectivity conventions; its technical documentation even distinguishes virtual downstream connections used for queries.[^8] Generated basin statistics must therefore match the source definition and geographic mask.

WorldClim 2.1 represents 1970–2000 monthly terrestrial climate at specified grid resolutions.[^9] It is useful for distributional Earth reference comparisons, but matching three global means cannot establish seasonal, spatial or mechanistic climate skill. Eleven passing oceanic-age distribution metrics similarly do not reconstruct crust creation, destruction, local flowlines or subduction provenance.
