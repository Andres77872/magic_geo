# Deep Implementation Plan

This plan executes the `r1.md` review as a CLI-first causal planet generator. The system treats the final map as a derived view over physical layers, not as the primary state.

## Current Scope

No GUI is implemented. The deliverables are:

- Python API/config layer.
- C++ native simulation core for expensive operations.
- CLI commands.
- Seed YAML config.
- JSON, CSV, and Markdown outputs.
- Runtime backend inspection, including OpenCL probing.

## Research-Driven Stack Decisions

| Area | Decision | Reason |
| --- | --- | --- |
| Python packaging/native build | `setuptools` editable install + CMake shared-library build | `scikit-build-core` + `pybind11` was researched as the preferred Python extension path, but this machine lacks `Python.h` for Python 3.13. The runnable implementation keeps Python packaging pure and builds the native library with CMake. |
| Python/C++ boundary | `ctypes` over a plain C ABI | Avoids unavailable Python C headers while preserving the requested split: Python API/CLI layer, C++ heavy compute layer. The C++ library returns JSON for Python to decode. |
| CLI | Typer | Type-hint driven CLI with subcommands, good ergonomics for config-heavy tools. |
| Config | YAML + Pydantic v2 | YAML is human-editable for seeds; Pydantic validates typed planetary, mesh, tectonic, climate, hydrology, erosion, compute, and output parameters. |
| Internal mesh v0 | Fibonacci sphere graph + optional geodesic icosahedron + cube quadtree LOD and HEALPix/S2-compatible metadata | Dependency-free spherical point set remains default; subdivided icosahedral graphs are available for simulation-oriented adjacency; generated outputs include deterministic cube-quadtree, equal-area ring-pixel, and cube-face token indices for coarse queries/render sampling. |
| Future mesh backends | Native HEALPix/S2/native multi-resolution mesh | V0 compatibility metadata now exposes HEALPix-inspired equal-area pixels and S2-inspired cube-face tokens, while true library-compatible topology, native simulation cells, and multi-resolution simulation meshes remain planned. |
| Heavy compute | C++20 + optional OpenMP | Mesh, plate, hydrology, and erosion loops are native. OpenMP is used if CMake finds it. |
| GPU path | Optional CUDA/OpenCL acceleration with CPU reference semantics | `compute.backend` supports `auto`, `cpu`, `opencl`, and `cuda`; automatic selection uses actual generated cell count and device qualification. Dense plate-assignment and smoothing kernels are accelerated, but the authoritative v3 spherical-overlap crust transport currently executes on CPU. Accelerator reconciliation, parity evidence, and performance policy for that transport remain pending. |

### Phase 0: Planet Parameters

Implemented in `WorldConfig`. Validates radius, gravity, rotation, axial tilt, orbital eccentricity, luminosity, pressure, greenhouse factor, target ocean fraction, internal heat, and age.

Current model uses these values in temperature, seasonality, sea-level targeting, and tectonic intensity. The Python enrichment layer also exports a `planet_parameters` snapshot and v0 `planet_realism_checks` for the r1 Phase 0 validation questions: whether the generated temperature regime supports liquid water, whether gravity and pressure can support a stable atmosphere, whether rotation yields plausible atmospheric-cell bands, and whether surface water matches the configured ocean/water inventory.

### Phase 1: Spherical Mesh

Implemented in C++ as default `fibonacci_sphere` plus optional `geodesic_icosahedron`.

Each cell stores:

- explicit `position_3d` and `normal_3d` unit vectors.
- latitude/longitude.
- authoritative native polygon and area: `spherical_voronoi_control_volume_v1` for Fibonacci sites or `spherical_barycentric_control_volume_v2` for geodesic vertices. Each cell exports counter-clockwise `control_volume_vertices_3d` and edge-aligned `control_volume_edge_neighbor_ids`.
- graph neighbors. For `geodesic_icosahedron`, `cell_count` is a target and the generated resolution is the first valid subdivided icosahedron size at or above that target.
- v0 HEALPix-inspired equal-area pixel IDs and S2-inspired cube-face tokens over cell centroids, exported as compatibility/query metadata rather than native simulation topology.
- display boundary rings derived from the authoritative native control-volume vertices, with perimeter, polygon-area replay, area-error fraction, and geometry-quality metrics.
- v0 `cell_adjacency_edges` records with undirected endpoint IDs, great-circle distance, midpoint, directional bearings, elevation delta, approximate shared boundary-segment endpoints/length/mismatch/quality, transition flags, and edge classes.

The mesh is intentionally not a render projection. Generated outputs expose each cell centroid as high-precision `position_3d`, the sphere surface normal as `normal_3d`, and `cell_area_model` plus total/minimum/maximum/mean/CV area summaries. Fibonacci sites are closed into true spherical Voronoi polygons by gnomonic half-plane clipping; a nearest-site query certifies every final vertex against omitted sites. The geodesic backend explicitly joins spherical primal-edge midpoints and face centers into a barycentric dual. Signed spherical area replay rejects reversed polygons, reciprocal edge checks require identical endpoints, and both partitions close to the configured planet surface. Strict Python validation independently replays polygon areas, topology, Voronoi bisectors, shared endpoints, and Euler counts. The separate `neighbors` graph remains the process stencil: `neighbor_count` still controls Fibonacci climate/hydrology/sediment adjacency, while geodesic stencils follow primal edges. `cell_adjacency_edges` and downstream watershed/territorial ledgers still use their current one-segment schema; that schema does not yet encode the geodesic dual's two-segment bent boundary. The `mesh_lod.index = cube_quadtree_v0` and `spherical_spatial_index.index = healpix_s2_compat_v0` records remain deterministic compatibility/query indices over centroids, not library-compatible native HEALPix/S2 topology.

### Phase 2: Plate Tectonics

Implemented in C++.

- Seeds plates on the sphere.
- Assigns cells by nearest spherical seed.
- Gives each plate an angular velocity axis/speed and crustal bias.
- Rotates every plate center around its axis on each configured model step, reassigns fixed mesh cells to the nearest moved center, and recomputes plate boundaries before crust/topography evolution.
- Exports `plate_kinematic_model` plus `plate_motion_history` records containing every center/rotation, full cell ownership, boundary and reassignment counts, canonical spherical-overlap CSR with its dominant categorical-source witness, contributor and destination coverage diagnostics, source/transported/post-process inventories, endpoint transport distances, oceanic event IDs, and split signed transport/process/total crust and elevation deltas.
- Exports assigned-cell summaries for each final plate: initial/final center, cumulative rotation, cell count, area, mean crust age/density/thickness, dominant crust type, dominant lithology, boundary activity, and v0 mean heat-flow/thermal-state diagnostics.
- Computes relative velocity across plate-neighbor edges.
- Classifies convergent, divergent, and transform influence fields.
- Groups connected collision, subduction, and rift candidates into explicit v0 tectonic zone records with source cell IDs, plate pairs, boundary edge IDs/length, representative cells, dominant crust/lithology/landform, and zone-strength evidence.
- Groups connected v0 fault systems from transform/convergent/divergent boundary signals, plate-boundary adjacency, transform-fault relief, and volcanic activity. Cells expose fault-slip, seismic-hazard, recurrence-interval, and fault-system ID diagnostics.

NOAA's three-boundary taxonomy is the controlling model for v0.

The kinematic clock uses configured nominal intervals in Ma, scaled relative to the retained 5 Ma reference step, rather than calibrated physical time. Each previous plate-attached source control volume is forward-rotated and intersected against the fixed Eulerian target partition. Raw spherical overlap areas transport extensive crust volume, density-volume, and age-volume moment; destination areas are not normalized, preserving explicit kinematic gaps and multiple coverage. The overlap ledger's dominant incoming source is only the categorical-selection witness, not a separate compatibility surface or the transport rule. Native code directly checks all three source-to-transported inventories; Python replays source rows, mixtures, destination/global multiplicity identities, telemetry bounds, inventory units/deltas, gap/overlap balance, and the complete ordered post-transport rule chain. A separate bounded O(N²) Python geometry implementation ignores native CSR discovery and reconstructs moving intersections/coverage for Fibonacci 128 and geodesic 162, matching native edge pairs/multiplicity exactly and area within `2.21e-6 km2`; it is capped at 1,024 cells pending an independent spatial index. Ten reasons expose exact positive/negative/net state-moment changes, but explicitly do not claim material-reservoir provenance. If the mesh is too coarse for the configured plate count/motion and a plate receives no cell, generation still fails explicitly. Equal-horizon cumulative rotation and controlled fixed-domain first-order refinement pass; a new two-backend v3 moving-domain diagnostic retains `time_step_convergence_demonstrated=false` because Fibonacci has nondecreasing L2 fields and both backends retain categorical mismatch. The overlap path is CPU-authoritative pending accelerator reconciliation, and physically calibrated plate reconstruction remains future work. The destination coverage arrangement has a 16,384-fragment local cap. Legal 180°/step, 32-plate stress cases pass on Fibonacci 512 (2,279 edges, 17 contributors, multiplicity 5, 92 arrangement lines, 1,844 fragments, source relative error `5.97e-15`, destination error `3.01e-6 km2`) and geodesic 642 (2,692 edges, 24 contributors, multiplicity 7, 132 lines, 3,835 fragments, source error `1.176e-14`, destination error `7.26e-6 km2`), but they do not establish exhaustive worst-case behavior.

### Phase 3: Crust, Age, Lithology

Implemented in C++.

Cell crust type, age, density, thickness, lithology, and volcanic potential are derived from plate bias and boundary influence and exported in JSON/CSV:

- the initial continental mask ranks a one-pass graph-smoothed, plate-biased potential with self-weight `0.77` and selects the configured `tectonics.continental_crust_fraction_target`; initial component count, largest component, boundary-edge count, target/actual fraction, smoothing contract, and one-hop transitional margin model are exported in `plate_kinematic_model`;
- each transition exports every spherical-overlap contributor in canonical destination-major CSR, its dominant categorical-source witness, prescribed source motion and remap-residual distances, coverage/gap/overlap diagnostics, and separate transport, process, and total numeric deltas;
- quiet oceanic crust ages by the configured effective Ma per procedural step, while divergent boundaries rejuvenate it and convergent boundaries record subduction-style events;
- oceanic crust is young near divergent boundaries and deeper with age;
- existing oceanic crust is rejuvenated at spreading boundaries without reinterpreting old continental transitional crust as oceanic;
- continental collision produces orogen/craton tendencies;
- rifts and sedimentary basins emerge near divergent continental settings;
- volcanic arcs emerge near convergent mixed settings;
- convergent ownership transfers can form explicit `accreted_terrane` crust.

### Phase 4: Initial Topography and Bathymetry

Implemented in C++.

Elevation combines:

- explicit isostatic elevation;
- thermal oceanic subsidence;
- ridge uplift;
- orogenic uplift;
- volcanic uplift;
- trench subsidence;
- rift subsidence;
- transform fault lowering;
- secondary deterministic roughness.

Large forms come from tectonics; noise is secondary. Continental potential uses the one-pass partition smoothing above, while secondary relief is independently smoothed for four passes at self-weight `0.58`. The v2 relief contract adds `500 m` continental freeboard and quadratic convergence response: `20,000 m` continental-orogen uplift, `17,000 m` oceanic-trench subsidence, `15,000 m` volcanic-arc uplift, and reduced `1,400 m` trench cancellation on volcanic-arc cells. These causal coefficients increase relief and coastline complexity without a post-hoc elevation multiplier. Each component is exported per cell, summarized globally, and validated as the initial elevation sum.

### Phase 5: Sea Level and Oceans

Implemented in C++.

Sea level uses `volume_constrained_connectivity_ocean_flood_v3`, independently of the configured initial continental-crust fraction. A deterministic union-find sweep activates equal-elevation groups from low to high and tracks native area plus elevation-area sum for the largest flooded component. Within each interval it solves `L = (1000 * ocean_water_inventory_km3 + sum(area_km2 * elevation_m)) / sum(area_km2)`. An in-interval solution closes `sum(area_km2 * water_depth_m / 1000)` exactly; when a connectivity change creates a discontinuity, the nearest valid interval endpoint is retained. Only the selected largest component receives marine `water_depth_m`. Disconnected cells below that surface remain non-marine and pass to the Phase 8 depression policy, which may preserve them as freshwater lakes or saline basins or leave them as dry closed terrain. Zero inventory produces no marine cells, while sufficiently high inventory can produce an all-marine world with no land basins. Land/sea state is recomputed after every erosion stage.

Top-level `sea_level_model` metadata exports configured/selected ocean volume and closure error, total/target/selected ocean area diagnostics, selected area and cell fractions, area-target errors, connected-ocean component count, below-sea-level land count/area, recomputation scope, and the limitation `cell_column_volume_without_subcell_bathymetry_straits_or_exact_coast_polygons`. Strict validation independently reconstructs volume from high-precision cell area/depth fields, rebuilds negative-elevation components, and replays the interval solver; it requires the marine mask to be a largest-area negative component and the selected volume/area to match the replay. This enforces one graph-connected ocean and uses unequal native areas correctly. `ocean_fraction_target` is retained only as an area diagnostic. The Earth-like `1,338,000,000 km3` setting follows the USGS estimate for oceans, seas, and bays, close to NOAA's `1,335,000,000 km3` ocean estimate. It does not allocate total planetary water among oceans, ice, groundwater, lakes, and atmosphere, and it cannot recover bathymetry or a real narrow strait with no represented cell-center path.

A Python graph diagnostic pass now exports connected `landmasses`, connected `marine_regions`, explicit connected `continental_shelves`, and candidate `marine_chokepoints` for straits/narrows. Cells carry `landmass_id`, `island_class`, `marine_region_id`, `continental_shelf_id`, and `marine_chokepoint_id`, and summary fields report continent/island counts, largest landmass, open-ocean/inland-sea/shelf region counts, continental-shelf area/depth/edge metrics, largest marine region, and chokepoint/strait counts.

### Phase 6: Climate Base

Implemented in C++.

Temperature uses latitude, season, luminosity, orbital eccentricity, greenhouse factor, elevation lapse rate, ocean moderation, and a v0 ocean-current thermal anomaly. The configured base temperature is interpreted as the global area mean after local elevation-lapse and ocean-current anomalies are area-centered on every climate recomputation. Ocean moderation affects seasonal amplitude, while the annual marine-temperature offset is explicitly zero. Luminosity, greenhouse, pressure, and the latitude term remain global controls; the latter uses a normalized 47 C, cubic sine-of-latitude curve whose 11.75 C continuous-area offset is recorded in `climate_model`. NOAA's circulation bands motivate the latitude pressure/rainfall structure.

Cells expose annual temperature plus exactly twelve monthly temperature values and an explicit r1 `climate_class` derived with the 30-subtype Beck et al. Koppen-Geiger criteria. `climate_model` records the v4 formula, zero annual marine offset, and local-centering scope `elevation_lapse_ocean_current`, and declares `mass_conserving_atmosphere = false` and `transient_climate_resolved = false`; `climate_classification` records the input fields, 0 C temperate/cold boundary, arid-class precedence, complete legend, coverage, and the limitation that a single generated monthly climatology cannot supply observational-ensemble confidence. Cells also expose a prevailing wind vector derived from latitude bands and rotation rate, monthly seasonal wind east/north arrays with mean speed and reversal diagnostics, v0 atmospheric-cell labels with surface-pressure anomaly, vertical-motion, and divergence diagnostics, explicit distance-to-marine-water, continentality, oceanic-humidity availability, and marine-influence class fields, v0 connected `climate_continentality_regions`, v0 seasonal humidity-regime diagnostics, ocean-current east/north vectors with temperature/moisture effects, and `climate_energy_balance_records` with per-cell monthly top-of-atmosphere insolation, seasonal range, orbital variability, albedo, absorbed shortwave, outgoing longwave, greenhouse trapping, net radiative balance, equilibrium-temperature residual, and energy-stress diagnostics. A v0 ocean-circulation pass projects each marine current vector onto the best-aligned neighboring marine cell, exports per-cell speed, signed poleward transport, heat transport, convergence, upwelling, regime, and system fields, groups connected thermal/directional regimes into `ocean_current_systems`, and materializes `ocean_current_transport_edges` with distance, alignment, system crossings, and marine-region crossings.

### Phase 7: Precipitation

Implemented in C++.

Rainfall combines equatorial convection, mid-latitude storm belts, an explicit drying multiplier centered near 30 degrees in both hemispheres, ocean distance, relief, and hemisphere-aware seasonal monsoon forcing. `climate.subtropical_drying_strength` controls the dry-belt response; land seasonality increases with continentality while ocean seasonality remains moderated, and the monthly multipliers preserve the approximate annual mean. A global thermal-moisture-capacity factor scales every month by `clamp(exp(0.04 * delta_temperature_c), 0.35, 2.25)`, using base temperature relative to 15 C plus the same stellar and greenhouse temperature forcing used by the temperature model. This gives colder configured worlds less atmospheric moisture and warmer worlds more, while remaining exactly 1.0 for the default Earth controls. The 4%/C response is deliberately lower than saturation-vapor-pressure scaling because global precipitation is energy and circulation limited; the bounds are safety limits for diverse configurations, not a conserved atmospheric-water solver. The generic template retains `precipitation_scale = 1.0`; the calibrated Earth-like seed explicitly uses `0.8`.

Rainfall also includes v0 ocean-current moisture, wind-path humidity transport, orographic, and rain-shadow multipliers. The humidity pass traces each cell's prevailing wind path upwind across neighboring cells, accumulates ocean/lake moisture fetch, and applies simple terrain rainout.

Cells now expose a v0 vapor-budget ledger: evaporation, moisture convergence, orographic rainout, precipitation recycling fraction, vapor deficit, and closure residual. The engine also exports `climate_seasonal_histories`, which group cells by atmospheric circulation band and project monthly humidity storage, evaporation, moisture convergence, precipitation, humidity export, vapor deficit, residual, seasonal wind east/north and speed, wind divergence, monsoon, and drying-risk terms from the generated monthly climate fields. ### Phase 9: Erosion and Sedimentation

Implemented in C++.

Runs configurable iterations that co-evaluate stream-power and lithology-dependent pairwise hillslope tendencies before a combined terrain commit:

```text
erosion ~ K[lithology] * A^m * S^n
edge_source_depth ~ min(0.45, D / resistance[lithology]) * elevation_drop / source_degree
edge_volume_km3 = edge_source_depth * source_area_km2 / 1000
edge_target_depth = edge_volume_km3 * 1000 / target_area_km2
```

Landlab's stream-power framing is the reference model for v0.

The native engine exports the explicit r1 `SimulationClock` concept as `simulation_clock.clock_type = coupled_geodynamic_stage_clock_v12` and materializes the executed feedback loop in linked water-budget, plate-motion, hillslope, fluvial, glacial, and Earth-system histories. Stage 0 captures initial plate domains and crust at a zero-duration nominal interval, then stabilizes sea level, climate, the causal land-water partition, routed hydrology, and numerical-pit correction or zero-material deferral. Each erosion transition advances the configured nominal interval, rotates plate centers, reassigns domains, recomputes boundary kinematics, and transports/evolves plate-attached crust. It then evaluates tectonic-elevation, hillslope-sediment, and stream-power tendencies before terrain commit; hillslope and stream consume the prior stabilized surface/hydrology with updated crust state. Those tendencies form a provisional terrain, fluvial sediment routes over the prior flow graph while using provisional elevation for accommodation, and finite alluvium/bedrock partitioning commits terrain and sediment before the bounded stabilization loop. One final zero-duration cryosphere stage derives ice, performs bulk glacial transport and inventory/terrain commit, repeats the same stabilization order, then recomputes cryosphere state on the stabilized terrain/climate. Numeric correction events consume the current event-time inventory sequentially. Records expose exact nominal interval basis/source/start/end/duration, explicit operator semantics, stage water-budget volumes/residuals, alluvium entrainment, bedrock erosion, final inventory, source-partition and inventory-closure residuals, complete snapshots and transfers, recomputation counts, breach and temporary-lake metrics, and mean changes from the preceding stage. `cell.erosion_rate` remains a reference-step response; feedback exports it canonically as `mean_stream_power_response_m_per_reference_step`. ### Renderer

Implemented in Python as dependency-free SVG and PPM raster output.

The renderer projects generated spherical cells after simulation, rather than using the render projection as the internal world state. It supports equirectangular, Mollweide, and orthographic projections, optional SVG settlement labels, max-cell low-detail sampling, routes, settlements, sacred-area markers, ruin markers, symbolic SVG elevation contour layers, and v0 terrain styling from elevation, neighbor relief, water depth, reefs, ice, aridity, sediment, rivers, and landforms. The `render-raster` path writes a binary PPM raster with deterministic causal terrain texture, reef tinting, route overlays, and settlement markers. This is now a v0 terrain-styled SVG/raster renderer, but still not a full artistic renderer with advanced texture synthesis or sophisticated multi-scale cartographic styling.

### Calibration

Implemented as v0 internal realism diagnostics exported in `planet_realism_checks`, `geology_realism_checks`, `climate_realism_checks`, `hydrology_realism_checks`, `biome_realism_checks`, and `worldbuilding_realism_checks`, plus v0 external-reference-range diagnostics exported in `calibration_checks`.

`planet_realism_checks` directly cover the r1 Phase 0 validation questions with bounded metrics and evidence counts: generated temperatures and surface water support liquid water, gravity and configured pressure are in an atmosphere-stable window, rotation and generated atmospheric-cell bands are plausible, and reconstructed ocean cell-column volume matches the configured ocean inventory while area remains a secondary diagnostic.

`geology_realism_checks` directly cover the r1 geology validation questions with bounded metrics and evidence counts: major mountain belts near convergent/orogenic cells, trench candidates near convergent boundaries, shallow oceanic highs near divergent boundaries, volcanic arc candidates paired with nearby trench/convergent oceanic cells, transform candidates forming continuous chains, and a land/ocean hypsometric bimodality index. These checks are diagnostic reports over the generated causal fields, not proof of a fully physical plate/relief solver.

`climate_realism_checks` directly cover the r1 climate validation questions with bounded metrics and evidence counts: subtropical precipitation deficits relative to equatorial/mid-latitude reference land, equatorial ocean-influenced humidity, rain-shadow dryness, continental interior temperature-range contrast, cold-current coastal moisture reduction, and warm-current coastal moderation. Strict validation also pins the v4 climate-model constants, including zero annual marine offset and every thermal-moisture reference, response, and bound; independently reconstructs the emitted thermal anomaly and factor from `planet_parameters`; reconstructs both the continuous latitude identity and the generated discrete area-mean temperature after centered local adjustments; enforces twelve months; and checks the declared equilibrium/non-conservative limitations. These checks are diagnostic reports over the generated climate fields, not a replacement for a mass-conserving atmospheric/ocean model.

`hydrology_realism_checks` directly cover the r1 hydrology validation questions with bounded metrics and evidence counts: river paths reaching valid sinks, river flow moving downhill over the filled surface, tributaries merging through nondecreasing flow accumulation without cycles, deltas constrained to low coastal sediment-rich river cells, and watershed boundaries following relative topographic divides. These checks are diagnostic reports over the generated drainage fields, not proof of a fully physical river-evolution model.

`biome_realism_checks` directly cover the r1 biome validation questions with bounded metrics and evidence counts: deserts coincide with water deficits, forests coincide with available water, tundra appears because of cold/frost/altitude/ice controls, savannas appear only in warm seasonal climates, and mangrove-labeled cells are constrained to warm wet coasts. These checks, the v0 `species_range_records`, and the v0 `wildfire_spread_histories` are diagnostic reports over the generated biome and climate/soil fields, not a replacement for a dynamic vegetation model with population-scale species composition or stochastic disturbance physics.

`worldbuilding_realism_checks` directly cover the r1 worldbuilding validation questions with bounded metrics and evidence counts: large settlements have water access, routes avoid expensive terrain barriers, political regions originate around connected settlement networks, political borders follow natural barriers, and resources depend on geology or causal physical context. `causal_upstream_evidence_worldbuilding_realism_checks_v1` independently replays every metric, target score, evidence field, record, and summary. These checks are self-consistency reports over generated human-geography records, not observational calibration or proof of a full endogenous history simulation.

The current checks compare generated distributions against broad Earth-like ranges inspired by the r1 dataset targets: ETOPO-style relief/bathymetry metrics, WorldClim-style annual/monthly climate metrics, HydroSHEDS-style river/endorheic watershed metrics, biome fractions, and Natural-Earth-style coastline coverage. `coastal_land_fraction` is the fraction of land cells with a one-hop marine neighbor, so its numerical value is mesh-resolution dependent; the checked production regression is explicitly the 4,096-cell reference configuration. The stricter external reports remain separate from these broad built-in checks.

The `derive-targets` CLI command can derive target JSON from local ESRI ASCII, GeoJSON, shapefile/DBF, dimensioned OPeNDAP ASCII, WorldClim GeoTIFF ZIP, HydroBASINS archive-catalog, and HydroRIVERS shapefile-ZIP sources. Matched Natural Earth and ETOPO statistics use the exact native Fibonacci centers and, for coastlines, the symmetric neighbor topology. ETOPO source names are preserved for provenance, while generated comparison names distinguish below-sea-level surface extent and nonnegative relief from the separately selected connected marine inventory. The WorldClim path validates twelve aligned scalar GeoTIFFs, decodes none/LZW/Deflate strips, applies geographic transforms/NODATA masks, and derives land-only annual temperature, precipitation, and monthly-temperature-range aggregates. The HydroBASINS path verifies the catalog and all nine regional archives, then requires aligned, complete `ENDO` and `SUB_AREA` values from each active DBF record. The HydroRIVERS path checksum-verifies the global archive, streams all active DBF records, selects terminal reaches over the declared upstream-area floor, and fits log upstream distance against log upstream area without loading the 873 MB DBF table. Generated relief, climate, watershed-area, and Hack-fit metrics are independently reconstructed from cell and watershed records rather than trusting summary-only values. Source manifests pin SHA-256, URL, version, license, citation, period, units, CRS, resolution, processing, and acquisition date; provenance survives derivation and evaluation.

The `calibrate` CLI command distinguishes metric coverage from fit and preserves provenance. `--require-all-metrics` gates coverage; `--require-all-passed` gates complete fit after writing the report. For the current v3 authoritative 4,096-cell seed, eight of eleven empirical metrics pass. Natural Earth coastline is `0.383800` against source `0.484034` and fails the lower bound `0.434034`; ETOPO below-sea-level extent `0.724365234375`, mean nonnegative elevation `887.167699 m`, and span `14,802.686265 m` all pass; WorldClim land temperature, seasonal range, and precipitation pass at `6.670534 C`, `16.959733 C`, and `825.960 mm/y`; HydroBASINS endorheic count `0.092150` passes while area fraction `0.416375924` fails high; HydroRIVERS exponent `0.736076284` fails high while log RMSE `0.296058473` passes. This is evidence for one reference, not a calibrated generator distribution.

`calibrate-ensemble` applies those same targets to the explicit members in `configs/calibration_ensemble.r1.json`, generates each unique seed/resolution coordinate once, and preserves per-member checks plus per-metric, per-dataset, and named-group aggregates. The report records normalized-config, matrix, and target-bundle hashes; separates complete coverage from fit; writes before either optional gate exits; and reproduces byte-identically. All ten checked members cover all eleven targets and none passes all targets. In the six-member seed group, Natural Earth passes 0/6, complete ETOPO 2/6, complete WorldClim 1/6, complete HydroBASINS 0/6, and complete HydroRIVERS 4/6. In the five-member resolution group, the corresponding counts are 0/5, 1/5, 2/5, 0/5, and 2/5. Tolerances are model-fit ranges, not confidence intervals. WorldClim archives are fetched but never redistributed because their license limits use to academic/non-commercial contexts without prior permission; HydroBASINS and HydroRIVERS archives remain local under HydroSHEDS terms. A generated Pfafstetter-equivalent basin hierarchy and raw HydroRIVERS reach-density fitting remain future work.
